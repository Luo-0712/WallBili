# MVP 阶段二实现与验证

日期：2026-10-15。分支：`feat/mvp-phase2`，基于已合并阶段一的 `main`（`f98f096`）。用户已确认阶段一可用，本阶段沿用原生 WBI 接入与 mpv。

## 实现与约定

- `CatalogImporter` 读取合集全部分页，展开视频全部分 P，使用 BVID/CID 去重；两个来源可共享同一目录条目。分页重复、网络失败或中途取消不会提交半份快照。不可访问视频记录来源问题；已知 CID 保留，未知 CID 不凭空补齐。
- `LibrarySession` 串行处理队列编辑、播放结束和进度检查点。队列项使用独立 ID，重复加入同一分 P 仍可独立排序/删除。当前项身份不随排序变化。
- 播放结束只由 mpv `end-file` 推进；只有 `reason=eof` 增加完成次数。媒体失败标记后跳过，列表循环在所有候选都失败时停止；不会用固定时长推算结束，也不会将解析成功算作播放完成。
- `MpvQueuePlayer` 将 `start-file` / `end-file` 的原生 `playlist_entry_id` 关联到本次加载 ID。旧流的 stop/EOF 不影响新流，加载尚未返回时的 EOF 也不会丢失。一个 mpv 进程承担当前音视频会话。
- SQLite schema v1 包含目录、来源、队列和播放检查点。保存使用一个事务，队列外键、唯一 ID 和位置约束共同防止破损快照；失败写入回滚，新版本 schema 拒绝覆写。采用小型本地库的完整快照事务，不面向超大目录的高频写入优化。
- 只保存稳定内容身份和本地状态；解析时取得临时媒体资源，数据库不接受媒体会话、签名 URL、Cookie 或请求头字段。mpv 路径单独存为本地偏好。
- 正常退出与周期检查点保留 Playing/Paused 意图；重新启动后按身份重新取流，恢复进度与音量。用户停止时归零并禁止启动自动播放。恢复失败保留当前项，可修正播放器路径后手动恢复。
- 删除当前项播放删除位置的后继项；无后继则停止，暂停状态保留。删除目录项同时移除全部对应队列项和来源关系；移除来源保留目录与队列。

| 检查 | 结果与证据 |
|---|---|
| 全解决方案构建 | 包括 WPF 与 Windows 桌面原型；零警告、零错误 |
| 阶段一协议行为回归 | 56 个测试；`work/content-tests.xml` |
| mpv 实际解码与控制回归 | 3 个测试；`work/player-tests.xml` |
| 阶段二目录、队列、存储和真实解码 | 21 个测试；`work/library-tests.xml`，覆盖分页、分 P、两来源、刷新去重/失败原子性、排序/删除、循环、失败跳过、旧/早到事件、三种恢复意图、SQLite 回滚/版本保护、无临时 URL 持久化 |
| 真实本地媒体连续播放 | 两来源四个分 P，FFmpeg 生成 H.264/AAC MP4；mpv 实际 EOF 连续推进；快速替换旧流不误推进；首项文件失效时跳过，后三项正常完成且失败项完成数为零 |

| Windows 界面、可见视频/可听音频 | 本环境不可运行；待按阶段二检查表实机验收 |
| Wallpaper Engine 共存 | 原型已提供并编译；尚未在 Windows 执行，未宣称通过 |

自动验证入口为 `bash scripts/verify.sh` 或 `pwsh scripts/verify.ps1`。脚本离线运行，不依赖 B 站服务；真实 mpv/FFmpeg 缺失时完整验收不能通过。

可选联网探针：

```bash
dotnet run --project tools/WallBili.Probe -c Release --no-build -- check-queue BV1xx411c7mD BV17x411w7KC --headless
```

该探针通过 seek 加快观察，不声称完整播完全部视频，也不代表实际音画输出或两小时稳定性已验证。临时库退出时清理，脱敏结果在忽略的 `work/` 中，关键证据保留于本文。
