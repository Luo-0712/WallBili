# 阶段三 Windows 验收

状态：实现与 Linux 自动验证已完成；Windows 实测自 2026-10-16 在 Windows 11 build 26200 上开始，下表按行区分已测与未测。用户已确认阶段一、二可用。不能将本表中的步骤或自动测试视为共存验收通过。

## 准备与首次使用

使用 Windows 10/11 x64、.NET 10 Desktop Runtime 和独立安装的可信 mpv 0.41.0。解压包后运行 `app/WallBili.Desktop.exe`。在窗口填写 mpv 路径，添加 BVID/链接或合集，选择目录条目加入队列，双击队列项。选择屏幕与填充/适应后点击“应用桌面设置”。关闭窗口会收起到托盘；彻底结束使用“退出”或托盘菜单。

数据与偏好位于 `%LOCALAPPDATA%\WallBili`，与前两阶段兼容。首次迁移可自行备份该目录。请先用用户已验证的来源；也可用 `BV1xx411c7mD` 与 `BV17x411w7KC`，可用性以当时 B 站返回为准。

当前后端在图标宿主之后查找**已存在且属于 Explorer 的 WorkerW**。只创建、移动、显隐和销毁 WallBili 自己的窗口，不发送创建桌面结构的消息，不修改 Wallpaper Engine 的父窗口、Z 序或设置。没有合适宿主时显示“等待可用的 Explorer 壁纸层”，每五秒重试；不能将此状态记为视频桌面通过。若阶段二原型在某个 Windows 布局下不适用，需先记录窗口结构与失败现象，再调整后端。Wallpaper Engine 后启动可能改变遮挡关系，必须观察实际画面。

分别按“Wallpaper Engine → WallBili”和“WallBili → Wallpaper Engine”启动。在同一目标屏幕与不同屏幕都记录：

| 检查 | 实测 |
|---|---|
| 实际可见画面与上下层叠关系，图标点击和框选结果 | 部分（2026-10-16）：实测同一 WorkerW 下子 Z 序为 WallBili 视频窗口在前、`WPEVideoWallpaper` 在后；Progman 子 Z 序为 `SHELLDLL_DefView` 在前、WorkerW 在后，因此图标层结构上位于视频层之上。**实际画面目视与图标交互未做** |

| WallBili 切歌/暂停/隐藏时，Wallpaper Engine 仍可操作 | 待测 |

## 音画同步与长期运行

固定媒体条件（例如 1080p/30fps）连续运行至少两小时，至少主动切换 20 次；覆盖开播、seek、切歌、网络恢复、睡眠和 Explorer 恢复。使用带明显音画同步标记的样例配合录屏/录音记录误差，初步目标 ≤200ms；同一 mpv 会话只是设计依据，不等于误差已经测得。

分别测量 WallBili 单独、Wallpaper Engine 单独和两者同时运行。可在 PowerShell 执行：

```powershell
.\measure-resources.ps1 -Minutes 120 -IntervalSeconds 10 -OutputPath wallbili-resources.csv
```

脚本只读采样 CPU 累计秒数、工作集、私有内存、句柄和线程，不记录命令行/媒体 URL。依据 PID/ParentPID 区分 mpv 与其他播放器；CPU 使用率由相邻 CPU 秒数增量除以墙钟间隔计算。GPU 使用率与显存请在任务管理器按相同测试窗口另行记录。检查预热后的增长趋势、切换后的回落和退出后的进程清理，而非只比较两次瞬时值。
